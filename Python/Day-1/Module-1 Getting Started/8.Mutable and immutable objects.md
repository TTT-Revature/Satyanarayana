# 8. Mutable and Immutable Objects

This is one of the most important concepts in Python because it helps us
understand memory behavior, variable assignment, function arguments, and
object references.

## 8.1 What is mutability?

Mutability refers to whether an object's contents or state can be
changed after the object is created.

Python objects are classified into two categories:

1.  Mutable objects
2.  Immutable objects

## 8.2 Mutable objects

Mutable objects can be modified after creation without creating a new
object.

Examples include lists, dictionaries, sets, and bytearrays.

``` python
numbers = [10, 20, 30]

print(numbers)

numbers[0] = 100

print(numbers)
```

Output:

``` text
[10, 20, 30]
[100, 20, 30]
```

The existing list object was modified.

We can verify this using `id()`:

``` python
numbers = [10, 20, 30]

print(id(numbers))

numbers[0] = 100

print(id(numbers))
```

The two IDs will be the same during this example's execution because the
list object was modified rather than replaced.

## 8.3 Immutable objects

Immutable objects cannot be modified after creation.

Examples include integers, floats, complex numbers, strings, tuples,
Booleans, bytes, frozensets, and ranges.

``` python
name = "Python"

name = name + " Programming"

print(name)
```

Output:

``` text
Python Programming
```

Python did not modify the original string. Concatenation created a new
string object, and `name` was reassigned to refer to it.

We can examine this using `id()`:

``` python
name = "Python"

print(id(name))

name = name + " Programming"

print(id(name))
```

The IDs will generally be different in this example.

## 8.4 Mutable vs. immutable objects

  Mutable                            Immutable
  ---------------------------------- -----------------------------------
  Can be modified after creation     Cannot be modified after creation
  Existing object can change state   Changes produce another object
  List                               Tuple
  Dictionary                         String
  Set                                Integer
  Bytearray                          Float
                                     Bytes

## 8.5 Understanding object references

``` python
a = [10, 20, 30]

b = a

b.append(40)

print(a)
print(b)
```

Output:

``` text
[10, 20, 30, 40]
[10, 20, 30, 40]
```

Both `a` and `b` refer to the same list object. Modifying the list
through `b` is therefore visible through `a`.

Conceptually:

``` text
Variable a ----\
                \
                 > Same list object: [10, 20, 30, 40]
                /
Variable b ----/
```

## 8.6 How to avoid reference-related problems?

Use copying when you need an independent list.

### Shallow copy

``` python
a = [10, 20, 30]

b = a.copy()

b.append(40)

print(a)
print(b)
```

Output:

``` text
[10, 20, 30]
[10, 20, 30, 40]
```

Another way:

``` python
b = a[:]
```

### Deep copy

A shallow copy does not recursively copy nested mutable objects.

``` python
a = [[1, 2], [3, 4]]

b = a.copy()

b[0][0] = 100

print(a)
print(b)
```

Output:

``` text
[[100, 2], [3, 4]]
[[100, 2], [3, 4]]
```

The outer lists are separate, but their nested lists are shared.

To copy nested objects independently, use `deepcopy()`:

``` python
import copy

a = [[1, 2], [3, 4]]

b = copy.deepcopy(a)

b[0][0] = 100

print(a)
print(b)
```

Output:

``` text
[[1, 2], [3, 4]]
[[100, 2], [3, 4]]
```

## 8.7 Mutable objects as function arguments

Python passes object references using an assignment-like argument
passing mechanism, often described as **call by sharing**.

``` python
def modify(numbers):
    numbers.append(40)

values = [10, 20, 30]

modify(values)

print(values)
```

Output:

``` text
[10, 20, 30, 40]
```

The function modifies the same list object supplied by the caller.

Now consider an immutable object:

``` python
def modify(x):
    x = x + 10

a = 20

modify(a)

print(a)
```

Output:

``` text
20
```

Assigning a new value to the local parameter `x` does not reassign the
caller's variable `a`.

## 8.8 Why are strings immutable?

Strings are immutable for several reasons:

1.  They are safer to share across different parts of a program.
2.  Their hash values can remain stable, allowing strings to be used as
    dictionary keys.
3.  They help prevent accidental modifications.
4.  They enable certain implementation optimizations.

**Teaching point:** When a list is modified, the existing list can
change. When a string is modified through an operation such as
concatenation, Python creates a new string instead of changing the
original one.
