# 5. Comments and Docstrings

## 5.1 What are comments?

Comments are explanatory notes written inside a program. Python ignores
comments during normal execution. They explain the purpose or logic of
code.

## 5.2 Single-line comments

A single-line comment starts with the `#` symbol.

``` python
# This program adds two numbers

a = 10
b = 20

result = a + b

print(result)
```

Output:

``` text
30
```

Inline comments are also possible:

``` python
age = 22  # Student's age
```

## 5.3 Multi-line comments

Python does not have a separate multi-line comment syntax. We can write
multiple lines beginning with `#`.

``` python
# This program demonstrates
# addition of two numbers
# using Python
```

Triple-quoted strings are sometimes used as comment-like blocks:

``` python
"""
This is a multi-line string.
It is not a comment.
"""
```

Important: Triple-quoted strings are string literals, not actual comment
syntax. If they are not assigned or used as docstrings, they are
generally discarded after evaluation.

## 5.4 What are docstrings?

A docstring is a string literal used to document a module, class, or
function. Docstrings are usually written using triple double quotes
(`"""`).

``` python
def add(a, b):
    """
    This function adds two numbers.

    Parameters:
        a: First number
        b: Second number

    Returns:
        Sum of the two numbers
    """
    return a + b


print(add(10, 20))
```

Output:

``` text
30
```

The string immediately after the function definition is its docstring.

## 5.5 Accessing docstrings

Python provides the `__doc__` attribute to access documentation.

``` python
def greet():
    """Displays a greeting message."""
    print("Hello!")

print(greet.__doc__)
```

Output:

``` text
Displays a greeting message.
```

We can also use:

``` python
help(greet)
```

This displays documentation about the function.

## 5.6 Comments vs. docstrings

  -----------------------------------------------------------------------
  Comments                            Docstrings
  ----------------------------------- -----------------------------------
  Start with `#`                      Usually written with triple quotes

  Explain code internally             Document modules, classes, and
                                      functions

  Not stored as accessible            Accessible using `__doc__`
  documentation                       

  Ignored by Python during execution  Stored as the object's
                                      documentation

  Primarily for developers reading    Useful for developers and
  code                                documentation tools
  -----------------------------------------------------------------------

## 5.7 Best practices

-   Write comments only when they clarify something important.
-   Avoid unnecessary comments.
-   Explain why something is done, not just repeat what the code does.
-   Use docstrings for reusable functions and classes.
-   Keep documentation updated when code changes.
