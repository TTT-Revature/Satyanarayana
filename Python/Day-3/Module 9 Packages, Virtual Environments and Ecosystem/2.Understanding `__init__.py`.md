## 2. Understanding `__init__.py`

### 2.1 What is `__init__.py`?

`__init__.py` is a special file commonly placed inside Python package directories. It can:

1. Mark a directory as a regular Python package.
2. Initialize package-level resources.
3. Expose selected functions and classes.
4. Provide a convenient package-level import interface.

Example:

```text
ecommerce/
├── main.py
└── users/
    ├── __init__.py
    ├── authentication.py
    └── profile.py
```

### 2.2 Is `__init__.py` mandatory?

No. Python 3.3 and later support **namespace packages**, which can exist without an `__init__.py` file when the import-path conditions are met.

Nevertheless, `__init__.py` is common in traditional application packages because it makes initialization and exports explicit.

### 2.3 Exposing functions through `__init__.py`

**users/authentication.py**
```python
def login():
    print("User logged in")

def logout():
    print("User logged out")
```

**users/profile.py**
```python
def view_profile():
    print("Displaying user profile")
```

**users/__init__.py**
```python
from .authentication import login, logout
from .profile import view_profile
```

Now another module can write:

```python
from users import login, logout, view_profile

login()
logout()
view_profile()
```

### 2.4 The role of `__all__`

`__all__` defines which names are exported by a wildcard import.

**users/__init__.py**
```python
from .authentication import login, logout
from .profile import view_profile

__all__ = ["login", "logout"]
```

Then:

```python
from users import *

login()
logout()
```

The wildcard import uses the names listed in `__all__`. This does not prevent explicit imports of other accessible attributes or modules.

### 2.5 Package initialization execution

Code inside `__init__.py` runs when the package is imported for the first time in a Python process.

```python
# users/__init__.py
print("Users package initialized")
```

```python
# main.py
import users
import users.authentication
```

The initialization message is generally printed once for that package module object in the process.

**Best practices:**
- Keep `__init__.py` lightweight.
- Avoid expensive database connections during imports.
- Avoid placing complicated business logic in it.
- Export commonly used functions only when it improves the package interface.
