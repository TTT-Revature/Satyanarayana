## 4. Virtual Environments and `venv`

### 4.1 What is a virtual environment?

A virtual environment is an isolated Python environment with its own package installation area and a reference to a Python interpreter. It lets different projects use different package versions without interfering with one another.

### 4.2 Why are virtual environments needed?

Imagine two projects:

| Package | Project A | Project B |
|---|---:|---:|
| Django | 4.2 | 5.2 |
| NumPy | 1.26 | 2.2 |

If both projects install packages into one shared global environment, version conflicts can occur. Separate virtual environments isolate their dependencies.

### 4.3 What is `venv`?

`venv` is a Python standard library module used to create virtual environments. It normally does not need to be installed separately.

### 4.4 Creating a virtual environment

Navigate to the project directory:

```bash
cd ecommerce
```

Create the environment:

```bash
python -m venv .venv
```

Explanation:
- `python` runs the interpreter.
- `-m` executes a module.
- `venv` is the virtual environment module.
- `.venv` is the environment directory name.

The directory can also be named `venv` or `env`; `.venv` is a common convention.

### 4.5 Activating a virtual environment

**Windows – Command Prompt**
```cmd
.venv\Scripts\activate.bat
```

**Windows – PowerShell**
```powershell
.venv\Scripts\Activate.ps1
```

**Linux/macOS**
```bash
source .venv/bin/activate
```

After activation, the terminal prompt generally displays `(.venv)`.

### 4.6 Installing packages inside the environment

After activation:

```bash
python -m pip install requests
```

The package is installed into the active virtual environment.

List installed packages:

```bash
python -m pip list
```

### 4.7 Deactivating an environment

```bash
deactivate
```

This returns the terminal to the previous Python environment.

### 4.8 Deleting an environment

Delete the `.venv` directory when it is no longer needed.

**Windows**
```cmd
rmdir /s /q .venv
```

**Linux/macOS**
```bash
rm -rf .venv
```

Recreate it with:

```bash
python -m venv .venv
```

### 4.9 Checking the active interpreter

```bash
python --version
```

Find its executable:

**Windows**
```cmd
where python
```

**Linux/macOS**
```bash
which python
```

From Python:

```python
import sys
print(sys.executable)
```

This helps verify that the intended interpreter is being used.

### 4.10 Virtual environments in VS Code

1. Open the project folder.
2. Press `Ctrl + Shift + P`.
3. Search for **Python: Select Interpreter**.
4. Select the interpreter inside `.venv`.
5. Open a new terminal if needed.

VS Code can then use the selected interpreter for running and debugging the application.
