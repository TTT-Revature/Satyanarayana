## 1. Packages and Package Structure

### 1.1 What is a Python module?

A **module** is a Python file (`.py`) containing reusable code. It can contain variables, functions, classes, constants, and import statements.

For example, an e-commerce application can separate user, product, and order functionality:

```text
ecommerce/
├── main.py
├── user.py
├── product.py
└── order.py
```

**user.py**
```python
def register_user(name, email):
    print(f"User {name} registered successfully")

def login_user(email, password):
    print("User logged in successfully")
```

**product.py**
```python
def display_products():
    print("Displaying all products")

def get_product_price(product_id):
    return 1500
```

**main.py**
```python
import user
import product

user.register_user("Rahul", "rahul@gmail.com")
product.display_products()

price = product.get_product_price(101)
print("Product Price:", price)
```

Modules improve code reuse, organization, debugging, and maintainability.

### 1.2 What is a Python package?

A **package** organizes related Python modules into directories.

```text
ecommerce/
├── main.py
├── users/
│   ├── __init__.py
│   ├── authentication.py
│   └── profile.py
├── products/
│   ├── __init__.py
│   ├── catalog.py
│   └── inventory.py
└── orders/
    ├── __init__.py
    ├── checkout.py
    └── payment.py
```

| Directory | Responsibility |
|---|---|
| `users/` | Registration, login, and profiles |
| `products/` | Product catalog and inventory |
| `orders/` | Checkout and payment |
| `main.py` | Application entry point |

### 1.3 Nested packages

A package can contain another package, called a subpackage.

```text
ecommerce/
├── main.py
└── payments/
    ├── __init__.py
    ├── transaction.py
    └── gateways/
        ├── __init__.py
        ├── razorpay.py
        └── stripe.py
```

Here, `payments` is a package, `gateways` is a subpackage, and `razorpay.py` is a module.

```python
from payments.gateways import razorpay

razorpay.process_payment()
```

### 1.4 Module vs package

| Feature | Module | Package |
|---|---|---|
| Definition | Python file | Directory-based collection of modules |
| Extension | `.py` | Directory |
| Purpose | Organize reusable code | Organize related modules |
| Example | `user.py` | `users/` |
| Contains | Functions, classes, variables | Modules and subpackages |

### 1.5 Real-world example: social media application

```text
social_media/
├── main.py
├── accounts/
│   ├── __init__.py
│   ├── authentication.py
│   └── profile.py
├── posts/
│   ├── __init__.py
│   ├── create_post.py
│   └── view_post.py
├── interactions/
│   ├── __init__.py
│   ├── likes.py
│   ├── comments.py
│   └── sharing.py
└── notifications/
    ├── __init__.py
    └── notification.py
```

Each package owns a distinct responsibility. For example, the like feature can be developed in `interactions/likes.py` without changing account or notification code.
