## 9. `.gitignore` and Basic Project Hygiene

### 9.1 What is Git?

Git is a distributed version control system. It helps developers track code changes, maintain project history, collaborate, create branches, restore previous versions, and manage repositories.

### 9.2 What is `.gitignore`?

`.gitignore` is a configuration file that tells Git which untracked files and directories to ignore.

Python projects generate temporary and environment-specific files such as virtual environments, Python cache files, logs, IDE settings, and local environment files. These usually should not be committed.

### 9.3 Creating `.gitignore`

Create a `.gitignore` file in the project root:

```gitignore
# Virtual environments
.venv/
venv/
env/

# Python cache
__pycache__/
*.py[cod]

# Environment variables
.env
.env.*

# Allow example environment configuration
!.env.example

# Log files
*.log

# Test and coverage files
.pytest_cache/
.coverage
htmlcov/

# Build files
build/
dist/
*.egg-info/

# IDE settings
.vscode/
.idea/

# Operating system files
.DS_Store
Thumbs.db
```

### 9.4 Common `.gitignore` entries

| Entry | Purpose |
|---|---|
| `.venv/` | Ignore virtual environment |
| `__pycache__/` | Ignore Python cache directory |
| `*.pyc` | Ignore compiled Python bytecode |
| `.env` | Ignore environment variables and secrets |
| `*.log` | Ignore log files |
| `.pytest_cache/` | Ignore pytest cache |
| `build/` | Ignore build output |
| `dist/` | Ignore distribution output |
| `.idea/` | Ignore PyCharm project settings |
| `.vscode/` | Ignore local VS Code settings |

### 9.5 Why ignore `.venv/`?

A virtual environment can contain interpreter files, installed third-party packages, package metadata, executables, and environment-specific configuration. It can become large and is not portable as a project dependency-management strategy.

Do not upload the whole environment to Git. Commit a dependency declaration such as `requirements.txt` or `pyproject.toml`, so another developer can recreate the environment.

### 9.6 Why ignore `.env`?

An `.env` file may contain sensitive information:

```env
DATABASE_URL=postgresql://user:password@localhost:5432/shop
SECRET_KEY=my-secret-key
API_KEY=your-private-api-key
```

Do not commit real credentials to a public repository. Instead, create `.env.example` with placeholders:

```env
DATABASE_URL=your_database_url
SECRET_KEY=your_secret_key
API_KEY=your_api_key
```

Commit `.env.example`, but ignore `.env`.

If a secret is accidentally committed, removing the file in a later commit does not remove it from Git history. Revoke or rotate the exposed credential and clean repository history if needed.

### 9.7 What if a file is already tracked?

`.gitignore` does not automatically stop tracking files that Git already tracks.

For example, if `.env` was committed earlier, run:

```bash
git rm --cached .env
```

Then commit the change. This removes the file from Git tracking while keeping the local copy.

### 9.8 Basic Git commands

Initialize Git:

```bash
git init
```

Check repository status:

```bash
git status
```

Stage files:

```bash
git add .
```

Commit changes:

```bash
git commit -m "Initial project setup"
```

Connect to a remote repository:

```bash
git remote add origin https://github.com/username/ecommerce.git
```

Push code:

```bash
git push -u origin main
```

### 9.9 Basic project hygiene checklist

- Use meaningful file and directory names.
- Organize code into modules and packages.
- Avoid writing the entire application in one file.
- Use virtual environments.
- Maintain dependency information.
- Use `.gitignore`.
- Never commit passwords or API keys.
- Write a useful README.
- Add automated tests.
- Follow consistent coding conventions.
- Remove unused imports and unnecessary files.
- Use meaningful variable and function names.
- Keep functions focused on one responsibility.
- Use logging instead of excessive debugging `print()` statements.

Python's style guide is PEP 8: https://peps.python.org/pep-0008/.
