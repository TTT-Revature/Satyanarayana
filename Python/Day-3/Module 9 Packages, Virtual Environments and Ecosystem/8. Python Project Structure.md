## 8. Python Project Structure

### 8.1 What is project structure?

Project structure describes how files, directories, modules, packages, tests, and configuration files are organized in an application.

A good structure improves readability, maintainability, scalability, collaboration, testing, and deployment.

### 8.2 A simple structure

```text
ecommerce/
├── main.py
├── users.py
├── products.py
├── orders.py
├── payments.py
├── database.py
├── config.py
├── test_users.py
├── test_products.py
└── requirements.txt
```

This can work for a small application, but becomes difficult to maintain as the project grows.

### 8.3 A more organized structure

```text
ecommerce/
├── .venv/
├── src/
│   └── ecommerce/
│       ├── __init__.py
│       ├── main.py
│       ├── users/
│       │   ├── __init__.py
│       │   ├── authentication.py
│       │   └── profile.py
│       ├── products/
│       │   ├── __init__.py
│       │   ├── catalog.py
│       │   └── inventory.py
│       ├── orders/
│       │   ├── __init__.py
│       │   ├── checkout.py
│       │   └── payment.py
│       ├── database/
│       │   ├── __init__.py
│       │   └── connection.py
│       └── config.py
├── tests/
│   ├── test_users.py
│   ├── test_products.py
│   └── test_orders.py
├── docs/
│   └── project_documentation.md
├── .env
├── .gitignore
├── README.md
├── requirements.txt
└── pyproject.toml
```

| File or directory | Responsibility |
|---|---|
| `.venv/` | Isolated Python environment |
| `src/` | Application source code |
| `ecommerce/` | Main application package |
| `users/` | User-related functionality |
| `products/` | Product-related functionality |
| `orders/` | Order-related functionality |
| `database/` | Database operations |
| `config.py` | Application configuration |
| `tests/` | Automated tests |
| `docs/` | Project documentation |
| `.env` | Local environment variables |
| `.gitignore` | Files Git should ignore |
| `README.md` | Project introduction and instructions |
| `requirements.txt` | Dependency list |
| `pyproject.toml` | Project and build configuration |

### 8.4 Separation of concerns

Separation of concerns means each module should be responsible for a specific functionality.

**authentication.py**
```python
def login_user(email, password):
    print("Validating user credentials")
```

**catalog.py**
```python
def get_products():
    return ["Laptop", "Mobile", "Headphones"]
```

**checkout.py**
```python
def place_order(user_id, product_id):
    print("Order placed successfully")
```

Each module performs a separate responsibility instead of combining unrelated functionality in one large file.

### 8.5 What is `README.md`?

`README.md` explains how to understand, install, configure, and run a project.

Example:

```markdown
# E-commerce Application

## Description
A Python-based e-commerce application.

## Features
- User registration
- User authentication
- Product management
- Shopping cart
- Order management

## Technologies
- Python
- SQLite
- Flask

## Installation
1. Clone the repository.
2. Create a virtual environment.
3. Install dependencies.

## Run Application
python -m ecommerce.main
```

A useful README helps another developer get started without needing to ask for basic setup instructions.

### 8.6 What is the `tests/` directory?

It contains automated tests that verify application behavior.

**src/ecommerce/users/authentication.py**
```python
def validate_email(email):
    return "@" in email
```

**tests/test_users.py**
```python
from ecommerce.users.authentication import validate_email

def test_valid_email():
    assert validate_email("test@gmail.com") is True

def test_invalid_email():
    assert validate_email("testgmail.com") is False
```

Install pytest if necessary:

```bash
python -m pip install pytest
```

Run tests:

```bash
python -m pytest
```

For a project using the `src` layout, configure the project for installation or set up the test import path appropriately. An editable installation is a common approach:

```bash
python -m pip install -e .
```

### 8.7 What is the `src` layout?

The `src` layout separates the importable Python package from the repository root.

```text
project/
├── src/
│   └── ecommerce/
│       ├── __init__.py
│       └── main.py
├── tests/
└── pyproject.toml
```

It helps prevent accidental imports from the repository root and encourages proper package installation and testing.
