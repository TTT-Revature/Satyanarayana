## 1. Unit Testing Concepts

### 1.1 What is testing?

Software testing is the process of checking whether a program behaves as expected. It helps verify that:

- The program produces correct results.
- Functions work with different inputs.
- Invalid inputs are handled properly.
- Changes do not break existing functionality.
- Errors and exceptions are handled correctly.

Example:

```python
def calculate_total(price, quantity):
    return price * quantity


print(calculate_total(100, 2))  # 200
print(calculate_total(250, 3))  # 750
print(calculate_total(50, 0))   # 0
```

Testing verifies whether the function returns the expected results for these inputs.

### 1.2 What is unit testing?

Unit testing is a software testing technique in which individual components of an application are tested independently. A unit can be a function, method, class, or small module.

For example, an e-commerce application might have these functions:

```python
def calculate_total(price, quantity):
    return price * quantity


def apply_discount(total, discount):
    return total - (total * discount / 100)


def calculate_delivery_charge(total):
    if total >= 1000:
        return 0
    return 50
```

Instead of testing the entire application at once, test each function independently.

### 1.3 Why is unit testing important?

| Benefit | Explanation |
|---|---|
| Early error detection | Identifies bugs during development |
| Code reliability | Verifies that functions produce expected results |
| Easier debugging | Helps identify the component causing an issue |
| Regression prevention | Checks that existing features still work after changes |
| Documentation | Demonstrates how functions are expected to behave |
| Maintainability | Makes future modifications safer |

### 1.4 Types of software testing

| Testing type | Description |
|---|---|
| Unit testing | Tests individual functions or components |
| Integration testing | Tests whether multiple components work together |
| System testing | Tests the complete application |
| Acceptance testing | Checks whether the application meets user requirements |
| Regression testing | Checks whether new changes have broken existing functionality |

**Example: Instagram-like application**

- Unit test: Check whether a post's like count increases correctly.
- Integration test: Check whether liking a post updates the database.
- System test: Check the complete post creation and liking workflow.
- Acceptance test: Verify that users can like and unlike posts as expected.

### 1.5 Test cases

A test case is a set of inputs, execution conditions, and expected results used to verify a particular functionality.

For a discount calculation function:

| Test case | Input | Expected output |
|---|---|---|
| Normal discount | Price = 1000, Discount = 10 | 900 |
| No discount | Price = 1000, Discount = 0 | 1000 |
| Full discount | Price = 1000, Discount = 100 | 0 |
| Invalid discount | Price = 1000, Discount = 120 | Error, if restricted by business rules |

A good test suite should cover normal cases, boundary cases, and invalid inputs.
