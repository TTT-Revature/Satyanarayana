## 7. Refactoring and Avoiding Duplicate Code

### 7.1 What is refactoring?

Refactoring means improving the internal structure of existing code without changing its external behavior.

The goals are to make code:

- Easier to read.
- Easier to maintain.
- Less repetitive.
- More reusable.
- Easier to test.

### 7.2 Example of duplicate code

Suppose an e-commerce application calculates discounts for different products:

```python
def calculate_mobile_discount(price):
    discount = price * 10 / 100
    return price - discount


def calculate_laptop_discount(price):
    discount = price * 10 / 100
    return price - discount


def calculate_tablet_discount(price):
    discount = price * 10 / 100
    return price - discount
```

All three functions perform the same calculation.

### 7.3 Refactoring using reusable functions

```python
def calculate_discount(price, percentage):
    discount = price * percentage / 100
    return price - discount
```

Reuse it:

```python
mobile_price = calculate_discount(20000, 10)
laptop_price = calculate_discount(60000, 15)
tablet_price = calculate_discount(30000, 5)
```

The repeated logic has been eliminated.

### 7.4 DRY principle

DRY stands for **Don't Repeat Yourself**. It encourages developers to avoid repeating the same logic in multiple places.

Example:

Bad:

```python
def calculate_mobile_price(price):
    return price + (price * 0.18)


def calculate_laptop_price(price):
    return price + (price * 0.18)
```

Better:

```python
GST_RATE = 0.18


def add_gst(price):
    return price + (price * GST_RATE)
```

### 7.5 Refactoring using classes

When multiple products share common properties and behavior, a class can encapsulate that behavior.

```python
class Product:

    def __init__(self, name, price):
        self.name = name
        self.price = price

    def calculate_discount(self, percentage):
        return self.price - (
            self.price * percentage / 100
        )


mobile = Product("Mobile", 20000)
laptop = Product("Laptop", 60000)

print(mobile.calculate_discount(10))
print(laptop.calculate_discount(15))
```

### 7.6 When should we refactor?

Consider refactoring when:

- The same logic appears repeatedly.
- Functions are becoming too long.
- Variables have unclear names.
- There are deeply nested conditions.
- A function performs too many responsibilities.
- Changes to one feature require modifications in many unrelated places.

**Important:** Do not refactor blindly. First ensure existing behavior is covered by tests. Run the tests again after refactoring.
