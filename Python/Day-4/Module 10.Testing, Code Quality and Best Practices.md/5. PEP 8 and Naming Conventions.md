## 5. PEP 8 and Naming Conventions

### 5.1 What is PEP 8?

PEP stands for Python Enhancement Proposal. PEP 8 is the official Python style guide. It provides recommendations for writing consistent, readable Python code.

Its goal is to make code easier to read and maintain.

### 5.2 Indentation

PEP 8 recommends four spaces per indentation level.

Good:

```python
def greet():
    name = "Satya"
    print("Hello", name)
```

Avoid inconsistent indentation:

```python
def greet():
  name = "Satya"
    print("Hello", name)
```

### 5.3 Naming conventions

| Element | Convention | Example |
|---|---|---|
| Variable | `snake_case` | `user_name` |
| Function | `snake_case` | `calculate_total()` |
| Method | `snake_case` | `get_user()` |
| Class | `PascalCase` | `ShoppingCart` |
| Constant | `UPPER_SNAKE_CASE` | `MAX_RETRIES` |
| Module | Short `snake_case` | `user_service.py` |
| Package | Short lowercase | `payments` |
| Internal attribute | Leading underscore | `_balance` |

Example:

```python
MAX_LOGIN_ATTEMPTS = 5


class UserAccount:

    def __init__(self, user_name):
        self.user_name = user_name

    def login_user(self):
        print("Login successful")
```

### 5.4 Line length

PEP 8 traditionally recommends:

- Maximum 79 characters for code lines.
- Maximum 72 characters for comments and docstrings.

Some projects adopt longer limits, such as 88 characters, when using tools like Black. Follow the project's configuration consistently.

Avoid:

```python
total_price = calculate_total_price(product_price, product_quantity, delivery_charge, discount_percentage)
```

Prefer:

```python
total_price = calculate_total_price(
    product_price,
    product_quantity,
    delivery_charge,
    discount_percentage
)
```

### 5.5 Blank lines

Use blank lines to separate logical sections:

```python
import math


MAX_PRICE = 10000


def calculate_area(radius):
    return math.pi * radius ** 2


def calculate_circumference(radius):
    return 2 * math.pi * radius
```

### 5.6 Imports

Organize imports in this order:

1. Standard library imports.
2. Third-party imports.
3. Local application imports.

Example:

```python
import os
import json

import requests

from shopping.models import Product
```

### 5.7 Comments and docstrings

Comments explain why something is done or clarify non-obvious logic.

```python
# Apply free delivery for orders above the threshold.
if total >= 1000:
    delivery_charge = 0
```

Docstrings describe modules, classes, and functions.

```python
def calculate_discount(price, percentage):
    """
    Calculate the discounted price.

    Args:
        price: Original product price.
        percentage: Discount percentage.

    Returns:
        Final price after discount.
    """
    return price - (price * percentage / 100)
```

### 5.8 Tools for checking code quality

| Tool | Purpose |
|---|---|
| `pycodestyle` | Checks PEP 8 style |
| `flake8` | Checks style and common code issues |
| `black` | Automatically formats code |
| `ruff` | Fast Python linter and formatter |
| `mypy` | Static type checking |
| `pylint` | Identifies potential problems and code-quality issues |

Install selected tools:

```bash
python -m pip install ruff black mypy
```

Run:

```bash
ruff check .
black .
mypy .
```
