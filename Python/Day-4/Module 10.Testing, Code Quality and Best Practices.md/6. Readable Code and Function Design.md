## 6. Readable Code and Function Design

### 6.1 What is readable code?

Readable code clearly communicates its purpose and logic.

Less clear:

```python
x = 500
y = 2
z = x * y
print(z)
```

More readable:

```python
product_price = 500
quantity = 2

total_price = product_price * quantity

print(total_price)
```

### 6.2 Use meaningful variable names

Avoid:

```python
a = 100
b = 5
c = a * b
```

Prefer:

```python
product_price = 100
quantity = 5

total_amount = product_price * quantity
```

### 6.3 Keep functions small and focused

A function should ideally perform one well-defined task.

Less maintainable example:

```python
def process_order(price, quantity, discount):
    total = price * quantity
    total = total - (total * discount / 100)

    if total >= 1000:
        delivery = 0
    else:
        delivery = 50

    final_amount = total + delivery

    print("Order placed")
    print("Total:", final_amount)
```

This function calculates prices, applies discounts, determines delivery, and prints the result.

A more focused design:

```python
def calculate_subtotal(price, quantity):
    return price * quantity


def apply_discount(total, discount):
    return total - (total * discount / 100)


def calculate_delivery(total):
    return 0 if total >= 1000 else 50


def calculate_final_amount(price, quantity, discount):
    subtotal = calculate_subtotal(price, quantity)

    discounted_total = apply_discount(
        subtotal,
        discount
    )

    delivery = calculate_delivery(discounted_total)

    return discounted_total + delivery
```

Each function has a clear responsibility.

### 6.4 Avoid deeply nested conditions

Less readable:

```python
if user_logged_in:
    if user_verified:
        if account_active:
            print("Access granted")
```

More readable:

```python
if not user_logged_in:
    print("Please log in")

elif not user_verified:
    print("Verify your account")

elif not account_active:
    print("Account is inactive")

else:
    print("Access granted")
```

### 6.5 Use early returns

Early returns can reduce nesting:

```python
def can_purchase(user, product):

    if not user:
        return False

    if not product:
        return False

    if product["stock"] <= 0:
        return False

    return True
```

### 6.6 Use type hints

Type hints make function inputs and outputs easier to understand.

```python
def calculate_total(
    price: float,
    quantity: int
) -> float:

    return price * quantity
```

Type hints do not automatically validate runtime values. They are primarily used by developers, editors, and static analysis tools.

### 6.7 Avoid unnecessary global variables

Avoid:

```python
total = 0


def add_price(price):
    global total
    total += price
```

Prefer:

```python
def add_price(total, price):
    return total + price


total = 0
total = add_price(total, 100)
total = add_price(total, 200)
```

This makes the function easier to test and reuse.
