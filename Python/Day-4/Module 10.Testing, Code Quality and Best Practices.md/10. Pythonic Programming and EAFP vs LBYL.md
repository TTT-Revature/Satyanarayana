## 10. Pythonic Programming and EAFP vs LBYL

### 10.1 What is Pythonic programming?

Pythonic programming means writing Python code in a way that follows Python's design philosophy and makes effective use of the language's features.

Pythonic code is generally:

- Simple.
- Readable.
- Concise without sacrificing clarity.
- Idiomatic.
- Maintainable.

Python provides a document called *The Zen of Python*, which summarizes many of these principles.

Run:

```python
import this
```

Some well-known principles include:

- Beautiful is better than ugly.
- Explicit is better than implicit.
- Simple is better than complex.
- Readability counts.
- Errors should never pass silently.

### 10.2 Non-Pythonic vs Pythonic code

**Example 1: Looping through a list**

Less Pythonic:

```python
numbers = [1, 2, 3, 4, 5]

squares = []

for i in range(len(numbers)):
    squares.append(numbers[i] ** 2)

print(squares)
```

Pythonic:

```python
numbers = [1, 2, 3, 4, 5]

squares = [number ** 2 for number in numbers]

print(squares)
# [1, 4, 9, 16, 25]
```

**Example 2: Swapping variables**

Less concise:

```python
a = 10
b = 20

temp = a
a = b
b = temp
```

Pythonic:

```python
a = 10
b = 20

a, b = b, a
```

**Example 3: Checking membership**

Less Pythonic:

```python
languages = ["Python", "Java", "C"]

found = False

for language in languages:
    if language == "Python":
        found = True
        break
```

Pythonic:

```python
languages = ["Python", "Java", "C"]

found = "Python" in languages
```

**Example 4: Checking whether a list is empty**

Less Pythonic:

```python
if len(products) == 0:
    print("No products")
```

Pythonic:

```python
if not products:
    print("No products")
```

### 10.3 EAFP — Easier to Ask for Forgiveness than Permission

EAFP is a Python programming style in which we try to perform an operation directly and handle exceptions if the operation fails.

Instead of checking whether an operation is possible beforehand, we attempt it and handle the error.

**Example: Reading a file**

```python
try:
    with open("products.txt", "r", encoding="utf-8") as file:
        data = file.read()

except FileNotFoundError:
    print("File does not exist")
```

The program attempts to open the file. If it does not exist, the exception is handled.

### 10.4 LBYL — Look Before You Leap

LBYL means checking whether an operation is possible before performing it.

**Example: Reading a file**

```python
from pathlib import Path

file_path = Path("products.txt")

if file_path.exists():
    with file_path.open("r", encoding="utf-8") as file:
        data = file.read()
else:
    print("File does not exist")
```

The program checks whether the file exists before opening it.

### 10.5 EAFP vs LBYL

| Feature | EAFP | LBYL |
|---|---|---|
| Full form | Easier to Ask for Forgiveness than Permission | Look Before You Leap |
| Approach | Try first, handle exceptions | Check first, then execute |
| Common construct | `try-except` | `if-else` |
| Example | Try opening a file | Check whether file exists before opening |

### 10.6 EAFP example: Dictionary access

LBYL:

```python
user = {
    "name": "Satya",
    "age": 24
}

if "email" in user:
    print(user["email"])
else:
    print("Email not available")
```

EAFP:

```python
user = {
    "name": "Satya",
    "age": 24
}

try:
    print(user["email"])

except KeyError:
    print("Email not available")
```

A third, often simpler option is:

```python
print(user.get("email", "Email not available"))
```

### 10.7 EAFP example: Division

LBYL:

```python
a = 10
b = 0

if b != 0:
    print(a / b)
else:
    print("Cannot divide by zero")
```

EAFP:

```python
a = 10
b = 0

try:
    print(a / b)

except ZeroDivisionError:
    print("Cannot divide by zero")
```

### 10.8 When should we use EAFP and LBYL?

Use EAFP when:

- An operation can fail for several reasons.
- You can handle the expected exceptions clearly.
- Checking beforehand would introduce unnecessary complexity.
- The state may change between checking and using it.

Use LBYL when:

- The condition is simple and reliable to check.
- The check is meaningful business logic.
- You want to avoid attempting an operation known to be invalid.

**Important:** EAFP does not mean catching every exception. Catch only exceptions you know how to handle. Avoid broad exception handling that hides programming errors.

## 11. Practical Application: Testing an E-Commerce Application

Let's combine several concepts into one small application.

### 11.1 Project structure

```text
ecommerce/
│
├── shopping.py
│
└── tests/
    └── test_shopping.py
```

### 11.2 shopping.py

```python
class ShoppingCart:

    def __init__(self):
        self.items = []

    def add_product(self, name, price, quantity):
        if price < 0 or quantity <= 0:
            raise ValueError("Invalid product details")

        self.items.append({
            "name": name,
            "price": price,
            "quantity": quantity
        })

    def calculate_total(self):
        return sum(
            item["price"] * item["quantity"]
            for item in self.items
        )

    def get_products(self):
        return sorted(
            self.items,
            key=lambda item: item["price"]
        )

    def get_product_names(self):
        return [
            item["name"]
            for item in self.items
        ]

    def has_products(self):
        return any(self.items)
```

### 11.3 tests/test_shopping.py

```python
import pytest

from shopping import ShoppingCart


@pytest.fixture
def cart():
    cart = ShoppingCart()

    cart.add_product("Mobile", 20000, 1)
    cart.add_product("Laptop", 60000, 1)
    cart.add_product("Mouse", 500, 2)

    return cart


def test_add_product(cart):
    assert len(cart.items) == 3


def test_calculate_total(cart):
    assert cart.calculate_total() == 81000


def test_get_products(cart):
    products = cart.get_products()

    assert products[0]["name"] == "Mouse"


def test_get_product_names(cart):
    names = cart.get_product_names()

    assert "Mobile" in names
    assert "Laptop" in names


def test_has_products(cart):
    assert cart.has_products() is True


def test_invalid_product():
    cart = ShoppingCart()

    with pytest.raises(ValueError):
        cart.add_product("Mobile", -100, 1)
```

## 12. Common Interview Questions

### 1. What is unit testing?

Unit testing is a software testing technique in which individual functions, methods, or components are tested independently to verify that they behave as expected.

### 2. What is the difference between unittest and pytest?

`unittest` is a built-in Python testing framework that commonly uses test classes and assertion methods. `pytest` is an external framework that supports simple `assert` statements, fixtures, and parameterized tests.

### 3. What is an assertion?

An assertion verifies whether a condition or expected result is true. If it is false, the test reports a failure.

### 4. What is PEP 8?

PEP 8 is the official Python style guide. It provides recommendations for indentation, naming conventions, imports, line length, and code formatting.

### 5. What is refactoring?

Refactoring is the process of improving the internal structure of code without changing its external functionality.

### 6. What is the DRY principle?

DRY means Don't Repeat Yourself. It encourages developers to avoid duplicating logic and instead create reusable functions, classes, and modules.

### 7. What is the difference between enumerate() and range()?

`range()` generates a sequence of numbers. `enumerate()` provides both an index and the corresponding value while iterating over an iterable.

### 8. What is the difference between any() and all()?

`any()` returns true when at least one element is true, while `all()` returns true only when every element is true.

### 9. What is the difference between sorted() and sort()?

`sorted()` creates a new sorted list, whereas `sort()` modifies the original list in place.

### 10. What is Pythonic programming?

Pythonic programming means writing readable, simple, clear, and idiomatic Python code that follows the language's conventions.

### 11. What is EAFP?

EAFP means Easier to Ask for Forgiveness than Permission. It attempts an operation and handles exceptions if it fails.

### 12. What is LBYL?

LBYL means Look Before You Leap. It checks whether an operation is safe or possible before attempting it.

### 13. What is a pytest fixture?

A fixture provides reusable setup, test data, or resources to test functions. It helps avoid repetitive setup code.

### 14. Why should we write unit tests before deploying an application?

Unit tests help identify errors early, improve reliability, and reduce the risk of introducing regressions when code changes.
