## 4. Introduction to pytest

### 4.1 What is pytest?

`pytest` is a popular third-party Python testing framework. It provides a simple way to write and execute tests.

Features include:

- Simple test syntax
- No need to create test classes for basic tests
- Readable assertion failures
- Automatic test discovery
- Fixtures for reusable setup
- Parameterized testing
- Exception testing
- A large plugin ecosystem

Install it:

```bash
python -m pip install pytest
```

### 4.2 Basic pytest example

Create `calculator.py`:

```python
def add(a, b):
    return a + b


def subtract(a, b):
    return a - b


def multiply(a, b):
    return a * b
```

Create `test_calculator.py`:

```python
from calculator import add, subtract, multiply


def test_add():
    assert add(10, 20) == 30


def test_subtract():
    assert subtract(20, 10) == 10


def test_multiply():
    assert multiply(5, 4) == 20
```

Run:

```bash
pytest
```

Or:

```bash
python -m pytest -v
```

Illustrative output:

```text
test_calculator.py::test_add PASSED
test_calculator.py::test_subtract PASSED
test_calculator.py::test_multiply PASSED

3 passed
```

Unlike `unittest`, pytest allows ordinary Python `assert` statements and provides useful failure details.

### 4.3 pytest naming conventions

By default, pytest discovers:

- Files named `test_*.py` or `*_test.py`.
- Functions beginning with `test_`.
- Methods beginning with `test_` inside test classes named `Test...`.

Example structure:

```text
project/
│
├── calculator.py
│
└── tests/
    ├── test_calculator.py
    └── test_users.py
```

### 4.4 Testing exceptions in pytest

Use `pytest.raises()`:

```python
import pytest


def divide(a, b):
    if b == 0:
        raise ValueError("Division by zero is not allowed")

    return a / b


def test_divide():
    assert divide(10, 2) == 5


def test_divide_by_zero():
    with pytest.raises(ValueError):
        divide(10, 0)
```

To check the error message:

```python
def test_error_message():
    with pytest.raises(
        ValueError,
        match="Division by zero"
    ):
        divide(10, 0)
```

### 4.5 Parameterized testing

Parameterization tests one function with multiple input combinations.

Without parameterization:

```python
def test_add_1():
    assert add(1, 2) == 3


def test_add_2():
    assert add(5, 5) == 10


def test_add_3():
    assert add(10, 20) == 30
```

Using `pytest.mark.parametrize`:

```python
import pytest


@pytest.mark.parametrize(
    "a, b, expected",
    [
        (1, 2, 3),
        (5, 5, 10),
        (10, 20, 30),
        (-1, 1, 0)
    ]
)
def test_add(a, b, expected):
    assert add(a, b) == expected
```

One test function checks multiple combinations.

### 4.6 Fixtures in pytest

A fixture provides reusable data, setup, or resources for tests.

```python
import pytest


@pytest.fixture
def user():
    return {
        "username": "satya",
        "email": "satya@example.com",
        "age": 24
    }


def test_username(user):
    assert user["username"] == "satya"


def test_age(user):
    assert user["age"] == 24
```

Pytest automatically supplies the fixture to test functions that request it by name.

### 4.7 unittest vs pytest

| Feature | unittest | pytest |
|---|---|---|
| Built into Python | Yes | No |
| Installation | Not required | Required |
| Basic test style | Class-based | Function-based or class-based |
| Assertions | `self.assertEqual()` | `assert` |
| Exception testing | `assertRaises()` | `pytest.raises()` |
| Parameterization | More manual | Built-in decorator |
| Fixtures | `setUp()` / `tearDown()` and other fixtures | Powerful fixture system |
| Plugins | Available | Extensive ecosystem |

**Recommendation:** Learn both. `unittest` is important because it is included with Python, while pytest is widely used for convenient and expressive automated testing.
